Compact Neural Interface FPGA + UWB Project

Previous Next

Project Summary

A compact, low power PCB stack that captures 512 channels of neural data from a custom recording chip, processes and frames it on a Lattice ECP5 FPGA, and sends it out over USB 3.0 or a UWB link for transcranial data transmission.

Project Details

  • 512 channels sampled at 15,625 Hz each (12-bit).
  • Lattice ECP5 FPGA (LFE5U-25F) with custom Verilog gateware.
  • 16.5 MB/s sustained streaming over USB 3.0 (FTDI FT600).
  • Framed serial output with CRC-12 for the UWB transmitter.
  • On-FPGA SPI chip configuration and stimulation control.
  • 6-layer KiCad boards, shrunk from 62 × 50 mm to 26 × 18 mm.
  • Battery powered with on-board Li-Po charging and ultra-low-noise LDOs.
  • C host daemon and live 512-channel Python scope.

Project Description

The Compact Neural Interface is the digital backbone for a 512-channel neural recording chip. The chip puts out eight serial data lines, each carrying 64 amplifiers (electrodes). This project includes the FPGA hardware that receives those lines, the Verilog that turns them into framed and error-checked packets, and the host software that records the data and plots it live. The long-term goal is a small, battery-powered stack that sits on the head and sends data through the skull over ultra-wideband (UWB) radio. The USB 3.0 path is the high-bandwidth link we use for development and validation.

I built this with Ben LeGrand. Both of us worked across the board hardware (FPGABoard) and the gateware and host tools (FPGA_512).

System Architecture

ADC / neural chip ──8 serial lines + 32 MHz clock──► ECP5 FPGA ──USB 3.0 (FT600)──► host PC
                                                         │
   deserialize → 4 framed lanes → arbiter → USB framer → 64 KB async FIFO → FT600
                                                         ├──► UWB serial framer (32 Mbit/s) → UWB chip
                                                         ├──► SPI programmer → chip configuration
                                                         └──► stimulation controller

The FPGA deserializes the eight bit-interleaved ADC streams. It pairs them into four lanes and packs each lane into a 132-word frame: a sync word, a lane ID, a frame counter, 128 data words and a CRC-12. The four lanes are interleaved into one USB stream and buffered through a block-RAM elastic FIFO into the FT600 USB 3.0 bridge. The same frames are mirrored onto a serial output for the UWB transmitter.

Hardware

All boards were designed in KiCad on 6-layer stackups and connect to each other through fine-pitch Hirose DF40C board-to-board connectors (0.4 mm pitch), so the whole system stacks vertically.

  • FPGA Board (V1), 62 × 50 mm: the first full development board. It has the ECP5 FPGA, an FTDI FT600 USB 3.0 FIFO bridge on USB-C, an MX25R6435F SPI configuration flash, a 16 MHz oscillator, a TPS62095 buck converter and TPS7A8101 low-noise LDOs for the 3.3 / 2.5 / 2.0 / 1.5 / 1.1 V rails, a JTAG header, a UWB header and a DF40C connector to the ADC board. An RP2040 running DirtyJTAG was added later so the FPGA could be programmed over USB without a dedicated programmer.
  • FPGA Mini (V2), 26.3 × 18.3 mm: the miniaturized version, about 84% smaller than V1 by area. To free up space, the USB interface moved to a separate breakout board. V2 adds a battery-powered power system: an MCP73831 Li-Po charger, TPS2120/TPS2121 power-path multiplexers, RP509Z buck converters, LT3045 ultra-low-noise LDOs for the sensitive analog rails, and TPS7A20 LDOs for the 2.5 / 2.0 / 1.5 / 1.1 / 1.0 / 0.8 V rails. It also has a 64 MHz SiT8008 MEMS oscillator with a CDCBT1001 clock buffer, 74AVC level translators to the neural and UWB chips, ESD protection, coaxial RF connectors, and a footprint for the custom UWB chip.
  • LDO Board (V2), 45.8 × 53.7 mm: a power board built around a bank of LT3042 ultra-low-noise linear regulators. It powers the neural recording chip, where supply noise feeds straight into the microvolt-level signals.
  • V2 Programmer / USB Adapter: a breakout that carries the FT600 USB 3.0 bridge, USB-C and the JTAG header for the Mini board, so the head-worn stack doesn't need them.
  • Connector Adapter (13 × 15 mm) and an A7 shield board: these adapt the DF40C connectors and link the boards to the existing chip carrier and ECP5 evaluation hardware during bring-up.

FPGA Gateware

  • ADC deserializer with auto-adjust: each serial line sends 64-cycle groups with a run of leading zeros, followed by four bit-interleaved 12-bit samples sent LSB first. The adc_auto_adjust module captures the whole group and detects whether the data starts after 11, 12 or 13 leading zeros. It then pulls the samples from the right offset, so the receiver stays aligned even when the chip's timing shifts.
  • Lane framing: pair_tdm_framer time-multiplexes channel pairs into four lanes, and usb_framer builds 132-word frames. Each frame has a DC-balanced sync word that is unique to its lane, a lane ID with a complement check, a 12-bit frame counter, and a CRC-12 that also covers the header. The chance of the receiver locking onto the wrong position is about 9 × 10-10.
  • USB streaming: lane_frame_arbiter round-robins the lanes into one stream. A 64 KB block-RAM elastic FIFO absorbs host-side stalls, and ft600_writer drives the FT600 245-mode FIFO interface with confirmed-acceptance gating, so no word is ever written twice or skipped.
  • UWB serial output: serial_framer mirrors the same framed data onto a serial line for the UWB transmitter, sending it as it arrives rather than buffering whole frames. Separate bring-up designs use the ECP5 PLL to multiply 16 MHz up to 64 MHz and drive the UWB chip's 4-bit parallel input header.
  • SPI chip programmer: spi_programmer stores up to 4,096 bits per channel of left/right SPI configuration data in block RAM. The host loads it over USB, and the module shifts it out at 500 kHz followed by a latch pulse. This replaced an earlier bit-banged SPI setup that ran from a DAQ device.
  • Stimulation controller: one host command starts a complete stimulation sequence of 1–255 pulses. A 32 kHz tick handles all timing: amplifier reset, stimulation enable and clock, a 4 ms period per pulse with a 1 ms pulse. Recording keeps streaming throughout.
  • Host command channel: the host can reset the chip, pulse or hold the front-end reset, switch in a ramp test pattern and start SPI or stimulation sequences, all without interrupting the data stream.

Host Software

  • adc_daemon (C): owns the FT600. A USB reader thread fills a 256 MB ring buffer, and a decoder thread checks every frame's sync, lane ID, sequence number and CRC. It builds 512-channel slices and handles WAV recording of any subset of channels. It also serves a Unix-socket API, and its --file replay mode lets frontend work happen without hardware.
  • adc_live.py: a real-time 8-panel scope (one panel per data line) with a command terminal. It uses peak-detect (min/max) decimation so fast signals show their true envelope instead of aliasing. A "single" mode freezes the view on full-rate data around the dominant frequency.
  • Diagnostics: adc_ctl for one-shot commands, stats for per-lane frame/CRC/sequence/drop counters, and async !drops, !crc and !seq events, so a lost sample is never silent. Tools for pattern checking, throughput benchmarks, raw capture and drop reproduction round this out.
  • Simulation: Icarus Verilog testbenches with ADC models and waveform-comparison scripts, plus an end-to-end test that replays recorded HDF5 sine data through a pattern generator.

Engineering Challenges

  • Stale FIFO reads at the USB interface: early FT600 tests dropped or duplicated one word about every 2,048 words, right at the FT600's 4 KB buffer boundary. The cause was that the FIFO read pointer and the output data register updated on the same clock edge. A "safe" fix of waiting one cycle after each write cut throughput to 0.028 MB/s. The final writer keeps data intact at full rate by only advancing the FIFO on a confirmed accept.
  • Clock-domain-crossing duplicates: the async FIFO between the 32 MHz ADC domain and the USB clock domain was rebuilt on block RAM with an output buffer. This removed duplicated words at the crossing.
  • Sample drops under host load: a 64 KB elastic FIFO now absorbs USB pauses from the host. The lane ID carries a drop counter, so any FPGA-side overflow is reported instead of silently corrupting data.
  • Toolchain quirk: Yosys' opt -undriven pass removed the DP16KD block-RAM cells the FIFOs depend on. Synthesis is now split around that pass.
  • Miniaturization: fitting the FPGA, power-path, charging, low-noise analog supplies, clocking and three board-to-board connectors onto a 26 × 18 mm, 6-layer board.

Status

The full 512-channel acquisition pipeline runs on hardware: ADC to FPGA to USB 3.0 to the live scope, with CRC-checked frames and drop reporting. The FPGA Mini (V2) and its supporting boards are in layout. Current work is finishing the miniaturized stack and bringing up the UWB transmission path.
