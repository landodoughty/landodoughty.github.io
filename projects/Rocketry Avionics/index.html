Rocketry Avionics Flight Electronics Project

Previous Next

Project Summary

Custom avionics for amateur rocketry: RP2350-based flight computers with sensing, data logging, LoRa telemetry, servo and motor control, and pyrotechnic ignition, plus a ground station to track and command them.

Project Details

  • Two flight computers: the Rice ECLIPSE AFS board and my own M.I.A. (Mission Independent Avionics).
  • RP2350B microcontroller with 16 MB QSPI flash and microSD logging.
  • Sensors: 6-axis IMU, ±64 g accelerometer, magnetometer, barometer, temperature and power monitoring.
  • USB-C or XT30 battery input with automatic power-path switching.
  • 8 buffered PWM outputs for servos and motor control.
  • M.I.A. adds 4 ignition channels with continuity sensing and u-blox GPS.
  • 915 MHz LoRa telemetry with a desktop ground station.
  • Pico SDK C++ sensor drivers with automated bench tests.

Project Description

Overview

Rocketry Avionics is a family of flight computers built around the Raspberry Pi RP2350B. The two boards share one core design: microcontroller, power system, sensor suite, storage and PWM outputs. ECLIPSE AFS is the flight computer for Rice ECLIPSE, and M.I.A. (Mission Independent Avionics) is my personal board. M.I.A. adds GPS, pyrotechnic ignition and telemetry so it can fly any mission on its own. Both are 4-layer boards designed in KiCad and are set up for JLCPCB assembly with LCSC part numbers.

ECLIPSE AFS

AFS is the flight computer for Rice ECLIPSE, the university's rocketry team. In the first version, team members each designed and tested one sensor circuit on its own (IMU, barometer, magnetometer, accelerometer, temperature and power sensing, plus the TPS2121 power path), then merged them into one main board. I led Version 2, a 50.8 × 87 mm 4-layer board that combines everything into one layout. It adds test points, LCSC part numbers and Gerbers ready for manufacturing. I also wrote the Pico SDK sensor drivers the team now uses.

M.I.A. (Mission Independent Avionics)

M.I.A. starts from the same core and adds everything needed to run a flight without other electronics:

  • Pyrotechnic ignition: 4 ignition channels, each switched by an AO3400A MOSFET, with a fuse, a zener clamp and a screw terminal. A high-impedance divider on each channel senses e-match continuity before launch.
  • GPS: a u-blox MAX-M10S GNSS receiver on its own 3.3 V rail, with an SMA antenna connector.
  • Telemetry: SPI telemetry connectors for a LoRa radio module.
  • Status: WS2812B RGB LEDs and indicator LEDs.
  • Layout: first routed on 6 layers, then converted to 4 layers, with impedance-controlled traces.

Firmware

The firmware uses the Pico SDK in C++. I wrote a self-contained driver library for each sensor, and all of them share the same pattern: a constructor that stores pins and settings, begin() to reset the chip and check its ID, setters that work at any time, and reads that return an error on bus failure. Each SPI driver sets its own baud rate and mode on every transaction, so sensors with different speed limits can share a bus with the SD card. The I2C drivers use timeouts, so a missing device can't hang the bus.

Every driver comes with a bench test that runs at boot. It checks that the chip responds and that settings read back correctly. It also checks that readings are physically plausible (about 1 g at rest, Earth's magnetic field, room temperature and pressure), and exercises the data-ready and interrupt pins, FIFOs, and continuous and non-blocking modes. At the end it prints a pass/fail summary table.

Telemetry and Ground Station

M.I.A. sends telemetry over a 915 MHz LoRa link (RFM95). The flight software runs a state machine: Idle → Armed → Powered Ascent → Coasting → Descent → Recovery. On the pad, the link is two-way: the rocket sends at 1 Hz and listens for commands. Once it launches, the radio switches to transmit-only and sends packets as fast as it can. Each packet carries position, velocity, acceleration, pitch/roll/yaw, altitude, temperature and the current flight state.

A Pico-based ground station receives the packets and logs them to an SD card. A desktop app built with Dear PyGui shows the data live, along with link RSSI and SNR. It also has ARM/DISARM controls, and its LAUNCH/RESET buttons are interlocked so they only work in the correct radio mode.

Status

The ECLIPSE AFS V2 board is ready for manufacturing, and its sensor drivers and bench tests are merged into the team firmware. The M.I.A. PCB is finished, and its firmware is moving from Arduino to the Pico SDK so it can share the same driver libraries.
